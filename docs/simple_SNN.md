# 最小测试用例：16 神经元环形 SNN

16 个 LIF 神经元组成单向环，阈值、权重与延迟都取整数，发放节律可以解析写出。
它提供首版运行所需的最小完整负载，并给出闭式的期望输出，用于在还没有第二个模拟器时
判定调度、查表、预取、交付与累加是否按设计工作。设计依据见[总体设计](overall_design.md)，
接口、容量口径与启动顺序见[类与接口草案](class_interfaces.md)。

本用例只有 16 个神经元，不能说明带宽与吞吐，也不能代替后续的随机稀疏负载，
覆盖边界见第 7 节。

## 1. 网络与神经元模型

| 项目     | 取值                    | 说明                             |
| -------- | ----------------------- | -------------------------------- |
| 神经元数 | N = 16                  | 全局 ID `0～15` 连续编号，不重排 |
| 连接     | `s → (s+1) mod 16`      | 每个源恰好一条出边，入度恒为 1   |
| 权重     | w = 1                   | 所有突触相同                     |
| 发放阈值 | θ = 1                   | 膜电位单位与权重一致             |
| 延迟     | d = 2 个最小仿真步（B） | 全网络相同，均为 A 的整数倍      |
| 状态     | S = 1（膜电位 V）       | 无自适应变量，无泄漏项           |
| 输入分量 | K = 1                   | 所有突触走输入通道 0             |
| 复位方式 | 硬复位到 0              | 软复位变体见第 7 节              |
| 初始状态 | 全部 V = 0              | 由外部刺激启动，见第 5 节        |

CGRA 黑盒函数（θ、权重与复位方式作为常量由闭包捕获，对应 S=1、K=1 的配置）：

```text
spike[n] = (V[n] + I[n] >= 1)
V[n+1]   = spike[n] ? 0 : V[n] + I[n]
```

语义与总体设计第 4.1 节一致：`update(S[n], I[n]) → (S[n+1], spike[n])`，
spike 在输入到达的那个子步判定，不推迟到下一子步。窗口内每个子步都按此式推进一次。

## 2. 时序参数

B 归一化为 1。延迟必须是 A 的整数倍，取 A = 2、M = A/B = 2，则 q = d/A = 1：
一个 A 窗口含两个最小步，延迟恰好跨越一个窗口。

| 符号    | 取值       | 说明                                   |
| ------- | ---------- | -------------------------------------- |
| B       | 1 个最小步 | 归一化单位                             |
| A       | 2 个最小步 | 最小突触延迟单元                       |
| M = A/B | 2          | 每个同步窗口两个子步                   |
| q = d/A | 1          | 事件在本窗口创建、下一窗口同一子步到期 |
| Dmax    | 1 个窗口   | 桶环只有 2 个桶，代次复用最频繁        |

取 A = 1、M = 1 时 q = 2，窗口退化为单子步：手算更简单，但事件创建与到期相隔两个窗口，
每窗口的压力更小。首版建议先用 A = 2 的版本，它把"本窗口创建事件、下一窗口交付"
这条最短路径跑满。

## 3. 行为推导

每个神经元一个周期内只收到一次权重 1，其余子步输入为零，因此 V 只在 {0, 1} 之间取值：
收到输入的那个子步 `V + I = 1` 判定发放并复位。发放沿环以每子步一个神经元的速度推进，
每 2 个子步（一个窗口）到达下一个神经元。

| 子步 n | 发放神经元 | 所在窗口 j（M=2） | 窗口内子步 |
| ------ | ---------- | ----------------- | ---------- |
| 0      | 0          | 0                 | 0          |
| 2      | 1          | 1                 | 0          |
| …      | …          | …                 | 0          |
| 30     | 15         | 15                | 0          |
| 32     | 0          | 16                | 0          |

通用式：神经元 k 在 `n = 2k + 32m`（m ≥ 0）发放；环周期为 `N × d/B = 32` 个子步，
每 32 个子步共 16 次发放。由于 2 整除 32，发放恒发生在窗口的子步 0，
事件到期步为 `2j + q×M = 2(j+1)`，即下一窗口的子步 0。

每个窗口的负载完全一致：1 次发放 → 1 次索引查询（1 条 `neuron-groups` + 1 条
`syn groups`）→ 1 个事件 → 1 条突触预取 → 1 次累加。四个数量相等是本用例最方便使用的
不变量。

## 4. 数据结构构造

用例的划分方式（单 PE 还是多 PE）只改变记录放在哪个 PE，不改变发放序列，
因此期望输出对划分不敏感，见第 6 节断言 6。

构造规则（`peOf(t)` 给出拥有目标 t 的 PE，`localIndex(t)` 给出其本地索引）：

```text
输入：N=16，d=2，A=2，q=1，划分函数 peOf / localIndex

1. 连接：对每个源 s ∈ [0, 16)，唯一出边 s → (s+1) mod 16，权重 1，延迟 q。
2. 按目标归属分流：目标 t 的入边来自源 s = (t-1+16) mod 16，
   这条突触放进 peOf(t) 的 backing store。
3. 每个 PE p 内按源编号升序排列本 PE 的突触记录，对第 i 条记录（源 s、目标本地索引 l）：
       synapses[i]       = { target: packTarget(l, 0), weight: 1 }
       synapse_groups[i] = { synapses_begin: i, synapse_count: 1, delay_windows: q }
       neuron_groups[s]  = { groups_begin: i, group_count: 1 }
4. 每个 PE 的 neuron_groups 覆盖全部 16 个全局源；第 3 步未出现的源写 group_count = 0，
   对该源的查询读到索引后即结束，不读取突触组。
5. neurons 区按本地索引存放 N × S 个 Scalar，本用例全部为 0。
```

单 PE（首轮建议配置）时全部记录都在 PE 0：

| 区              | 记录数 | 内容                                          |
| --------------- | -----: | --------------------------------------------- |
| `neurons`       |     16 | 全部 0                                        |
| `neuron_groups` |     16 | 源 s 对应 `{groups_begin: s, group_count: 1}` |
| `syn groups`    |     16 | `{synapses_begin: s, synapse_count: 1, q: 1}` |
| `synapses`      |     16 | `{target: packTarget((s+1) mod 16, 0), w: 1}` |

4 PE × 4 神经元的划分（PE p 拥有全局 ID `[4p, 4p+4)`）：

|  PE | 本地目标 | 前驱源         | 非零 `group_count` | 本 PE 记录数 | 跨 PE 的边    |
| --: | -------- | -------------- | ------------------ | -----------: | ------------- |
|   0 | 0…3      | 15, 0, 1, 2    | 4                  |            4 | 15 → 0（入）  |
|   1 | 4…7      | 3, 4, 5, 6     | 4                  |            4 | 3 → 4（出）   |
|   2 | 8…11     | 7, 8, 9, 10    | 4                  |            4 | 7 → 8（出）   |
|   3 | 12…15    | 11, 12, 13, 14 | 4                  |            4 | 11 → 12（出） |

每个 PE 都恰好有一次入跨边和一次出跨边，因此四个 PE 的远端投递路径都被走到；
每个 PE 的 16 条索引里有 12 条 `group_count = 0`，同时覆盖零长度记录的跳过路径。

## 5. 初始化与启动

- `neurons` 全部置 0，四个区按第 4 节填充。
- 外部刺激：在窗口 0 的子步 0 给神经元 0 注入增量 1（通道 0），
  由 `IM::initialize(initial_stimuli)` 在启动时注入并封闭窗口 0；其余窗口无刺激，
  仍显式调用 `closeExternalInputs()`。
- 若不想走刺激通路，也可以直接把神经元 0 的初始 V 置 1；此时启动后第一个子步即发放，
  但外部刺激的注入路径不被覆盖。建议用刺激。
- 建议首轮配置：P = 4（16 个神经元分 4 组）、L = 2、`nc_slots` = 2（不小于 L 且小于组数，
  让 NC 循环队列恰好绕一圈）、K = 1、S = 1、M = 2、`max_delay_windows` = 1；
  EQ、PF、查询槽与内存请求槽取最小值即可（同时存在的活事件不超过 1 条）。
- 变体 `nc_slots` = 1 可以按最紧的方式覆盖读入、计算、写回在同一槽位上的串行推进。

## 6. 期望输出与断言

1. **发放序列：** 神经元 k 恰在 `n = 2k + 32m` 发放；`[0, 32m)` 内累计发放 16m 次。
2. **节律：** 任一神经元相邻两次发放间隔恒为 32 个子步（16 个窗口）。
3. **每窗口负载：** 每个窗口恰好 1 次发放、PE 个数次 neuron_groups 查询、1 条组描述读取、1 个事件、1 条突触记录交付、1 次累加。
4. **交付计数：** 事件创建数 = 发放数 × 组数（= 1），交付条数 = 突触条数，
   且每 `(窗口, 子步, 目标, 通道)` 的累加次数恒为 1。第 7 节说明为什么这条断言不能用发放序列代替。
5. **屏障：** 每个窗口结束时五项条件同时成立，不存在必须等到窗口末尾之后才满足的工作。
6. **划分无关：** 单 PE 与 4 PE 划分给出完全相同的发放序列，含窗口内子步位置。
7. **数值精确：** V 只取 {0, 1}，权重与阈值都可精确表示，因此本用例的输出与浮点误差无关，
   可以作为逐位比较的基准用例。
8. **长跑：** 10^4 个子步后断言 1～3 仍成立，覆盖槽位回收与时间桶（q = 1 时桶环只有 2 个）
   的频繁复用。

## 7. 变体与不覆盖的内容

变体：

- **软复位：** `V[n+1] = V[n] + I[n] − θ×spike[n]`。硬复位会把重复交付的权重（V 收到 2）
  掩盖成同一次发放，对"重复累加、重复交付"类缺陷不敏感；软复位下同样的重复会让 V 留下 1，
  下一子步继续发放，形成连发。需要用发放序列检测重复类缺陷时改用软复位版本，
  或保留硬复位但依赖断言 4。
- **双波：** 给神经元 0 和神经元 8 各注入一次刺激，环上有两个独立波，
  此后每个窗口 2 次发放、2 个事件、2 条交付，覆盖同一窗口内的并发查询、并发预取与
  两笔同时在途的突触读取。
- **更长延迟：** d = 4（A = 2，q = 2），环周期 64，事件跨两个窗口停留，
  覆盖桶环第三个桶的使用与更远的预取窗口。
- **更细划分：** 8 PE × 2 神经元，使大多数边跨 PE；或 N = 64、4 PE × 16 神经元，
  覆盖更多 NC 分组与更薄的每 PE 负载。

不覆盖：同源多组与大组的分块预取、乱序返回、PF 不足导致的反压重试、EQ 溢出到 HE、
IM 溢出到 HI、窗口内靠后子步发放带来的处理尾链、事件延迟分布、任何带宽与吞吐结论
（规模太小），以及浮点误差对发放的影响（本用例数值精确）。
随机稀疏、带延迟分布的负载仍属于总体设计第 5 节保留的测试用例工作。
