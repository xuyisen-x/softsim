# 脑模拟专用硬件总体设计

本文根据架构草图与文字说明整理，作为 SoftSim 后续建模的设计草案，而非已实现功能的说明。
“已明确”表示原始描述或后续讨论中已确认的约束；“暂定理解”与“建议”均需进一步讨论。
开发与构建约定见 [开发指南](development.md)，已有内存时序接口见 [RamulatorWrapper](ramulator_wrapper.md)。
首版最小测试用例见 [16 神经元环形 SNN](simple_SNN.md)。

## 1. 整体架构与数据所有权

已明确的架构如下：

- 系统由多个处理单元（PE）通过片上网络（NoC）连接。
- 每个 PE 绑定一个 HBM 通道，拥有独占的内存地址空间。
- 每个 PE 分配并独占一部分神经元，负责其状态更新。
- 每个 PE 的神经元占据连续的全局 ID 区间，通过本地 index 加起始偏置得到全局 ID；神经元重排序由编译器负责。
- 仿真期间拓扑、突触权重和延迟保持不变，不支持突触可塑性、权重更新或连接增删。
- 每个 PE 包含 Neurons Management、Event Management 和 Isyn Management。
- 三个管理组件各自拥有独立、私有的 cache，不共享缓存容量或替换状态，彼此不会挤占缓存或驱逐对方的数据。
- NM、EM、IM 各自拥有独立的 HBM 读 credit 和写 credit，分别限制该组件可发放的在途读、写请求数；组件之间、读写之间均不借用额度。同一控制器的读、写 credit 上限总和分别不超过对应队列容量，保证有 credit 发放的合法请求被接受。
- spike 携带发放者 ID 与绝对发放步号 `emitted_step`，步号以最小仿真时间步 B 为单位；每个源神经元每个最小仿真步最多发放一次。
- 首版以瞬时全局通知代替具体 NoC：神经元发放时，所有 PE 的 Event Management 立即收到完整 spike，本地接收一次。
  发放步号由 NM 的更新任务写入消息；无本地相关突触的 PE 不产生突触事件。

草图中的 DRAM 在本文中对应 HBM，Cache 区域对应各组件独立的片上缓存。
cache 之间互不干扰；各组件的 HBM 请求仍访问该 PE 绑定的同一个通道，发放受各自读、写 credit 控制，通道带宽与请求仲裁另行建模。
各组件 cache 使用 SRAM 建模。首版采用简单、正确且可由电路实现的逻辑，
例如有界存储、读写端口、计数器、状态位和队列指针；不要求复杂的通用 cache 替换机制。
瞬时全局通知是首版明确采用的通信抽象，其 NoC 实现与完成检测留待后续设计。
EM 待查表的 spike 接收列表首版使用动态 `std::vector` 按需扩容，暂不建模该列表的硬件容量或入口反压。

以下表格描述单个 PE 的组件、存储及逻辑数据流。ID 仅用于本文交叉引用，不是硬件地址或神经元 ID。
存储项表示各组件私有存储的逻辑用途；组件内部的 cache/buffer 组织、容量和端口数仍待确定。

**已明确：当前设计中，突触按目标神经元所在 PE 存放。** 一个 PE 保存所有指向其本地神经元的
突触，并按发放者组织索引；同一源神经元的出突触可以分布在多个目标 PE。
远端 spike 到达后，接收 PE 查询自己的索引并累加自己的 Isyn，不需要远程读写神经元状态。

未来可能探索神经元与突触的彻底解耦；用户提出 Dalorex 作为潜在参考，目前仅为设想。
若改变突触归属，需要重新定义 NoC 消息、Event Management 与 Isyn Management 的职责及数据流。

## 2. HBM 数据结构

以下字段描述逻辑含义；已确定 `target` 内使用 2 bit 编码输入通道，其余结构体布局、总位宽、数值精度和对齐仍待确定。
索引可替代记录内 ID，不等于可以省略 spike 消息中的发放者标识。

| 数据结构        | 逻辑字段                            | 寻址与含义                                                                                                      |
| --------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `neurons`       | `states`                            | 保存本地神经元状态；由本地 index 定位，记录内无需重复保存 ID。状态数量由神经元模型决定。                        |
| `neuron-groups` | `syn_groups_start`, `length`        | 每条记录固定大小；按发放者对应的 index 查询，得到其突触组起点与组数。记录内无需 ID。                            |
| `syn groups`    | `synapses_start`, `length`, `delay` | 每项描述一段突触；同一组中的突触具有相同传播延迟，`length` 为突触条数。                                         |
| `synapses`      | `target`, `weight`                  | `target` 内的 2 bit 保存输入通道，其余位保存本地目标神经元索引；`weight` 保存权重。一个突触组对应一段连续记录。 |

索引查询见 F08–F09，事件入队与取出见 F10–F11，突触预取、EM 取出及向 IM 交付分别见 F13、F14a、F14b。

### 2.1 神经元状态与索引

已明确：CGRA 当前按黑盒建模，神经元状态是可变长度序列，状态数量由所选模型决定，不能在通用接口中写死。
本设计的简化 LIF 示例只保存膜电位 `[V_t]`；对于包含 `w_t` 的模型，则保存 `[V_t, w_t]`。
其他模型需要的状态由模型配置定义，上层不额外强制保存某种突触电流或其他内部变量。

CGRA 运行时仍使用同一神经元模型，抽象为 `output = f(input)`。
时间常数等固定参数在编译时吸收进 CGRA，模拟器中由 `std::function` 捕获；运行时可变参数计入 `states`，不另设参数输入。
因此，长度随模型配置变化；选定模型后可使用统一状态布局，不要求在同一 CGRA 的运行过程中切换模型。
状态步长根据配置的状态数量、各元素位宽及对齐计算，而非固定为一个标量或某个模型的结构体大小。
该配置内使用 `base + local_index × state_stride` 直接寻址，读取、预取和写回长度均由实际状态布局决定。
同一模型可通过输入状态表达行为差异。当前不展开模型内部参数语义，CGRA 按配置返回可变长度的 `std::vector` 结果即可。

### 2.2 突触索引的覆盖范围

首版每个 PE 保存覆盖所有全局源神经元的稠密 `neuron-groups` 表，直接以全局源 ID 作为 index，
通过 `base + source_id × record_size` 定位固定大小记录，不在记录内重复保存 ID。
若某个源没有指向本 PE 的突触，其记录的 `length=0`，EM 查询后结束处理，不读取突触组。
该索引覆盖所有源，并不只包含本 PE 独占的神经元；首版不引入稀疏映射或额外的压缩索引。

`syn_groups_start`、`synapses_start` 可以是通道内字节地址或数组偏移；目前只确定其定位作用。
`target` 打包本 PE 的目标神经元 index 与输入通道，具体约定见下一节。
同源、同延迟的突触优先连续存放，事件执行允许按块推进；具体物理分块布局归入第 5 部分。

### 2.3 突触目标与输入通道编码

已明确：每条 synapse 在现有 `target` 字段中借用 2 bit 保存 `input_channel`，编码范围为 0～3，
其余位保存本地目标神经元索引，不新增独立的类别字段。
若 `target` 总宽度为 W bit，则索引占 W−2 bit，可编码 `2^(W−2)` 个本地神经元。
总位宽及所借用位的位置尚待确定，编码和解码必须使用一致约定。

突触展开后先解码得到 `target_index` 和 `input_channel`，再累加对应分量；
不能将打包后的 `target` 直接作为神经元索引。配置 K 个输入分量时，有效通道须满足 `input_channel < K`。
类别由每条突触携带，因此一个同延迟 syn group 可以包含不同类别的突触，无须为类别额外拆组。

## 3. PE 内部模块

### 3.1 Neurons Management

已明确的职责：

1. 通过自己的 cache 从 HBM 流式读取神经元状态，利用预取隐藏访问延迟。
2. 将可变长度神经元状态与相应时刻的可变长度输入电流向量共同送入 CGRA 黑盒。
3. 接收更新后的状态及 spike，将状态汇聚后批量写回 HBM。
4. 将 spike 交给本地 Event Management 和 NoC。

CGRA 只作为黑盒，用一个 `std::function` 描述功能，以 `std::vector` 返回配置要求的可变长度结果，
不展开内部模型、参数和电流方程。结果提供后续所需的新状态及 spike 信息，具体元素语义由模型配置约定。
状态和输入电流共同构成一次调用的输入；二者长度及总输入长度都必须可配置。

| 项目           | 约束                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 状态数量 S     | 随模型变化，使用可变长度序列；更新结果保存该模型要求的全部状态。                                                          |
| 输入电流数量 C | 使用可变长度序列；目前 Isyn 提供 K 个分量，K 可配置为 1～4。若全部输入来自 Isyn，则 C=K；额外背景输入的接入方式仍待确定。 |
| 总输入长度     | 由实际状态和输入电流决定；运行时可变参数计入状态，不固定为某个模型的长度，也不强制填满 4 个 Isyn 分量。                   |
| 内部行为       | 由模型函数定义，按要求返回 `std::vector`；上层负责输入、输出和状态存储，不进一步限制模型细节。                            |
| 计算延迟 L     | 可编程，单位为 CGRA 硬件周期；给定配置下每组输入固定在 L 周期后输出。                                                     |
| 每组神经元数 P | 可编程；每组输入、输出长度由 P、状态数和输入分量数共同决定。                                                              |
| 启动间隔 II    | 固定为 1 个 CGRA 周期，入口条件满足时可以每周期接受一组完整输入。                                                         |
| 反压           | 仅在入口控制是否发射；接受输入后不能暂停计算或推迟输出。                                                                  |

例如在周期 c 接受输入，则在 c+L 输出结果；若下一周期也接受输入，则对应结果在 c+1+L 输出。
II=1 不代表 L=1，也不要求输入不足或结果空间不足时强行发射。这里的硬件周期不同于突触延迟的神经仿真时间步。
运行时仍使用同一神经元模型，输入分量的含义由配置确定；常量保留在函数内部，可变参数随 states 传入。
每组包含 P 个神经元与每个神经元在窗口内推进 A/B 个子步是两个不同维度。
窗口内保留已读入状态，逐子步使用对应输入完成更新，再写回窗口末状态；不将跨子步状态依赖视作可以任意并行的输入。

已明确：CGRA 输出的更新状态写入 Neurons Management 的独占 cache（NC），再伺机批量写回 HBM。
NC 按循环队列使用：读入端为后续神经元状态分配位置并发起预取，写回端批量提交已更新状态，
完成后回收位置供下一轮读入使用。读取、计算与写回在同一循环队列中流水推进，不限定为两块交替使用的缓冲区。
每个槽位或数据块保存神经元范围、有效长度及处理状态等元数据：

| 阶段           | 元数据需记录的含义                                         | 后续操作                                                                     |
| -------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 读入位置已分配 | 已保留空间，读取请求等待登记或提交。                       | 等待请求登记槽及 NM 读 credit 可用后发放，期间保留状态。                     |
| 已申请读       | 读取请求已接受，数据仍在途；分拆请求需跟踪各部分完成情况。 | 等待数据完整返回。                                                           |
| 已读到         | 状态数据可用。                                             | 输入电流就绪且输出位置可覆写时发射到 CGRA。                                  |
| 更新中         | 已向 CGRA 发射，记录对应槽位与结果到达周期。               | 保留覆写位置，接收固定延迟结果。                                             |
| 已更新         | 新状态已写入 NC。                                          | 窗口内尚有子步时保留状态继续更新；该数据块完成本窗口全部子步后伺机批量写回。 |
| 已申请写回     | 写回请求已接受，尚有未完成部分。                           | 跟踪写回完成，保持所需数据有效。                                             |
| 已写回         | 该数据块写回完成，无其他未完成访问占用。                   | 回收槽位，供读入端复用。                                                     |

各阶段按完成事件更新元数据，不能仅凭指针推进就假定此前请求已经完成。
Neurons Management 必须在入口检查 NC 是否有足够空间供结果覆写；空间不足时不发射新输入。
空间检查按实际状态长度计算，并计入已在途任务预留的覆写位置，不能将同一份空间重复承诺给多个结果。
已预留的位置在结果写入前必须保持可用，从而保证 II=1 下的固定延迟输出有处可写。
批量写回由 NM 独立安排，CGRA 输出不等待 HBM 写回完成。
不设置独立的 CGRA 缓冲额度参数，入口依据 NC 槽位及其元数据判断能否发射。

### 3.2 Event Management

已明确的职责：

1. 接收本地产生和 NoC 输入的 spike。
2. 根据发放者查询 `neuron-groups`，再读取对应的 `syn groups`。
3. 将突触组项目加入 event queues，等待相应仿真时间的调度。
4. 在处理当前 A 窗口时，将下一 A 窗口各子步被激活的突触预取至自己的 PF，再由 EM 读取并交给 Isyn Management。

首版瞬时通知传递 spike 的发放者 ID 和绝对发放步号，不传递其展开后的逐突触事件。spike 接收阶段由 EM 完成索引与组描述查询，
大规模突触读取安排在后续预取阶段。当前设计预期利用神经元更新期间的处理窗口完成这些工作，
暂不将同步发放或高扇出单独列为主要瓶颈。

Event queues 主要驻留片上缓存，允许溢出到 HBM；synapse prefetch buffer 仅用于预取，不向 HBM 溢出。
两者用途不同：前者保留未来工作，后者保存已发起或已返回的突触读取结果。

event queues 使用环形时间桶，按 A 窗口组织，并保留事件在窗口内的到期子步；A、B 与延迟关系见第 4 部分。
工作负载的最大延迟 Dmax 有限，但不设固定硬件最大值。桶的逻辑覆盖范围随模型配置，片上仅缓存所需部分，
其余事件及必要的桶元数据可存入 HBM，不将 Dmax 与固定片上桶数绑定。
桶保留绝对窗口号或代次，复用前确认上一代事件已处理完。EM 在当前窗口调度下一窗口到期的事件，
溢出记录保留所属时间桶及子步信息。

已明确：一个 spike 的每个 syn group 生成一个事件，同一源神经元每个 B 子步最多发放一次。
事件携带或可恢复到期时间、突触起点、突触数量及分批处理进度。
EM 从 spike 消息直接取得 `emitted_step`，按 `due_step = emitted_step + delay_windows × M` 计算事件到期步。
消息排队、查表和突触预取均保留该时间信息，不能用消息接收时刻、当前窗口起点或硬件周期推断发放步。
允许事件分块执行、乱序完成及合并，前提是保持贡献的目标、输入通道与到期子步语义，并在相应全局窗口屏障内完成。
同一源在一个 A 窗口内不同子步产生的 spike 是不同事件，不能丢失其子步差异。

已明确：EM 允许多笔突触读取同时在途。在等待一笔读取返回时，只要下一笔地址已知、PF 有可预留空间、请求已登记且 EM 读 credit 可用，
就可继续提交。同一组或多个组均可提供这些读取，一个大组按块推进，不要求整组同时放入 PF。
每笔请求提交前为返回数据预留 PF 空间，同时记录其事件、数据范围和完成状态。
PF 的已用容量包括已返回但尚未由 EM 取出并完成交付的数据，以及尚未返回的读取所预留的空间。
读取返回时将预留空间转为有效数据；EM 读取并将数据交付给 IM 后回收对应 PF 空间，IM 不直接访问 PF。
若 IM 暂不能接收，EM 保留待交付数据；空间不足就暂停新预取并保留未完成事件进度。
已登记但尚无读 credit 的请求保留 PF 预留空间并等待；取得 credit 后发放必须被 HBM 控制器接受，意外拒绝按第 3.5 节报错。
当前预取范围为下一 A 窗口，覆盖其中 A/B 个子步，并发发生在该窗口所需的多笔读取之间。

### 3.3 Isyn Management

已明确的职责是接收激活突触的 `target`、`weight` 及可确定的输入类别，只累加相应时间步新到达的权重，
并将结果提供给 Neurons Management。输入如何驱动神经元由 CGRA 黑盒函数定义，不由 Isyn Management 解释。
若模型需要突触衰减等持续状态，由模型决定是否将其纳入可变长度的神经元 `states`，上层不预设这些变量。
在当前 A 窗口内，为 Neurons Management 提供该窗口每个 B 子步的输入，同时累加下一 A 窗口各子步的输入。
累加主要发生在 Isyn buffer，容量不足时允许溢出到 HBM。
首版采用按绝对步号管理的多缓冲：IM 私有 `std::vector` 保存 `2M` 个步缓冲，M=A/B，
其中 M 个保存当前窗口各步输入，另 M 个累加下一窗口各步输入；不实现 IM 独立的 HBM 访问和 HI 溢出。
该简化见 [后续注意事项 N07](notice_me.md#n07im-的内存访问与溢出)。

首版外部刺激通过理想化方式直接加入 Isyn，由测试用例指定目标神经元、子步、输入通道与增量，
在对应输入被 NM 消费前完成注入。暂不建模刺激生成与传输的硬件或时延，具体实现留待后续补充，
见 [后续注意事项 N06](notice_me.md#n06外部刺激的实际实现)。

Isyn 的输入分量数可配置为 `K ∈ {1, 2, 3, 4}`，每个目标神经元每步保存 K 个独立的权重和。
这里按上下文将“可变位宽 1～4”解释为输入向量的分量数，而非每个数值占用 1～4 bit；
每个分量的数值位宽及精度另行确定。
逻辑上的单条累加操作为 `(due_step, target_index, input_channel, weight)`，
其中目标索引和通道从 synapse 的 `target` 解码得到，且 `0 ≤ input_channel < K`：

```text
# I：分步输入累加值；due_step：绝对到期步号；target_index：本地目标索引；input_channel：输入通道。
I[due_step][target_index][input_channel] += weight
```

本文沿用 `I[t]` 表示 Isyn buffer 的到达权重和及已注入的外部刺激增量，并不表示已经经过突触动力学计算的实际电流。
各分量的单位与含义由模型定义。不同类别分别累加，交给 CGRA 后分别驱动对应的内部状态，
不能在进入 CGRA 前跨类别求和。`K=1` 对应原有单标量方案；`K>1` 支持不同突触响应的分类输入。
分量数可配置不意味着一条突触必须携带 K 个权重；上述逻辑操作每次更新一个分量，物理接口的打包方式另行确定。
同一分量内的权重必须允许按模型语义相加；需要超过 4 个独立类别的模型不在当前接口范围内。

每个步缓冲保存绝对步号、可累加/已封闭状态、外部刺激完成标记、N×K 个 `float` 值及 N 个消费标记，N 为本 PE 神经元数。
按 `step % (2M)` 定位缓冲后，必须校验其绝对步号；`due_step` 决定累加到哪个缓冲，NM 的更新步号决定消费哪个缓冲。
首版所有步缓冲在初始化时定长，总数值容量为 `2M×N×K` 个 `float`。M>1 时要同时保存多个时间步的输入，不能压成仅两份单步数组。
窗口 j 对应当前步 `jM ... (j+1)M-1`，累加步为 `(j+1)M ... (j+2)M-1`；当前 M 个缓冲只消费，下一 M 个缓冲只累加。
全局屏障确认当前窗口全部消费、下一窗口全部贡献和外部刺激完成后，封闭下一窗口的 M 个缓冲，
再将旧当前窗口的 M 个缓冲清零、重标记为窗口 j+2 的步号并开放累加。首版不逐步提前复用。
例如 M=4 时共有 8 个步缓冲；步 1 和步 3 发放、延迟为 A 的 spike 分别累加到步 5 和步 7，不能混入同一个单步输入。
长延迟事件留在 event queues，到期窗口前再展开，不要求 Isyn 为 Dmax 范围内的每个子步分配完整数组。
槽位的消费、清零、复用及溢出副本的有效性必须统一管理。
每个分量均须正确消费、清零和溢出；对同一目标同一分量的并发累加、HBM 读改写及脏项驱逐，
需要保证没有更新丢失。CGRA 发射前必须确认该神经元本步全部 K 个分量已完成累加及外部刺激注入，
没有突触事件和外部刺激的分量为零。
容量与带宽预算应按实际存储布局计入 K 个分量及窗口内的子步数，不能沿用单标量、单子步的 Isyn 占用估算。

### 3.4 初始化与功能模型

仿真开始前，神经元状态及其他初始数据均可在 DRAM/HBM 的功能数据存储中任意初始化，
初始值由具体测试用例给出，不需要专门的硬件初始化流程。
实际数据由上层 backing store 保存，RamulatorWrapper 只模拟内存请求时序。
初始化直接设置 backing store；运行期间按实际访问字节数提交内存请求，数据可用时刻受模拟时序约束。

CGRA 只需按配置接受输入并返回 `std::vector`，当前不进一步讨论内部电流或背景模型。
运行期间外部刺激按第 3.3 节的理想注入方式处理，实际硬件实现记录在 [后续注意事项](notice_me.md)。
目前允许一定浮点误差，不要求逐位可复现；误差与 spike 翻转的验证问题记录在 [后续注意事项](notice_me.md)。

### 3.5 各组件的读、写 credit

已明确：每个 PE 内，NM、EM、IM 分别配置自己的读 credit 上限和写 credit 上限，共六份独立额度。
某组件用完读 credit 时暂停该组件的新读请求，写请求仍可使用其写 credit；其他组件也继续使用自己的额度。

首版采用“有 credit 发放就必须被控制器接受”的约定。对每个 PE 绑定的内存控制器分别校验：

- NM、EM、IM 的读 credit **配置上限之和**不超过该控制器的读请求队列容量。
- NM、EM、IM 的写 credit **配置上限之和**不超过该控制器的写请求队列容量。

容量取后端实际生效的 `read_buffer_size` 和 `write_buffer_size`，读写分别约束，不能合并计算或跨通道抵扣。
所有进入这两类队列的上层请求都必须经过 credit 控制，不允许其他请求绕过额度。
credit 从提交前占用到完成回调，回调不重入发放；在后端调用返回后的外部发放点，队列中的请求数不会超过已占用 credit 数，仍有 credit 时队列必有空位。
请求移出队列但尚未完成时仍占 credit，这一归还方式偏保守，首版先保持简单。

| 组件 | 读 credit 覆盖的 HBM 访问 | 写 credit 覆盖的 HBM 访问 |
| --- | --- | --- |
| NM | 神经元状态读取。 | 神经元状态写回。 |
| EM | neuron-groups、syn groups、synapses 读取，以及启用 HE 后的事件回载；这些读取共用 EM 自己的读额度。 | 启用 HE 后的事件溢出写入。 |
| IM | 启用 HI 后的输入回载及读改写中的读取。 | 启用 HI 后的输入溢出或写回。 |

首版按 `splitChannelRequest()` 拆分后的单个 HBM 子请求计 credit，每笔占用对应方向的一个 credit。
一笔逻辑访问拆成多笔时，可以随着 credit 归还逐笔提交，不要求一次拿到覆盖整笔逻辑访问的全部 credit。

1. 发放前必须同时满足对应 credit 可用、返回数据空间已预留或写数据保持有效等条件。credit 保证控制器接收，不代替请求登记槽或 NC/PF 空间等其他资源条件。
2. 调用 `send()` 前预扣一个 credit 并建立完成状态。合法请求应返回 true；若返回 false，视为队列容量配置或 credit 记账约束被破坏，报告错误并终止仿真，不走正常重试路径。
3. 接受后一直占用到该子请求的完成回调，完成时恰好归还一次。回调可能在 `send()` 返回前同步发生，因此不能等返回 true 后才扣减。
4. credit 归还只改变请求额度，不代表整个逻辑访问、功能数据复制或 Isyn 累加已经完成，也不直接释放 NC/PF 槽位。
5. credit 仅在初始化时设为配置上限，运行中随发放和完成变化，不在每周期或窗口切换时重置；它与 SRAM 端口的每周期吞吐额度分别管理。

credit 由上层组件请求管理逻辑维护，不改变 RamulatorWrapper 的通道级 outstanding 计数。
当前首版没有 EM 的 HE 写入及 IM 的独立 HBM 访问，这些未启用方向的 credit 可设为 0；实际需要发放请求的方向必须配置正值。
启用 HE/HI 后仍使用对应组件自己的 credit，不引入跨组件共享的 credit 池。
各组件具体分配多少额度暂不固定，后续确认事项见 [N08：credit 分配方案](notice_me.md#n08credit-分配方案)。

## 4. 时间语义与阶段重叠

### 4.1 时间单位与延迟

| 符号  | 含义与约束                                                                         |
| ----- | ---------------------------------------------------------------------------------- |
| B     | 神经元最小仿真时间步，归一化为 1，不指定毫秒等物理单位。                           |
| A     | 突触延迟最小单元，A/B 必须为正整数，可以大于 1。                                   |
| M=A/B | 每个同步窗口包含的最小仿真步数。                                                   |
| d     | 突触延迟，为 A 的正整数倍，不允许零延迟；用 B 为单位时，d/B 为 M 的正整数倍。      |
| Dmax  | 当前工作负载的有限最大突触延迟，不设固定硬件上限；事件桶规模随配置和存储需求变化。 |
| L、II | CGRA 的计算延迟与启动间隔，使用硬件周期计数，与 A、B 是不同时间尺度。              |

最小步以整数 n 编号，语义为 `update(S[n], I[n]) → (S[n+1], spike[n])`。
在子步 n 发放、延迟为 d 的 spike，到期子步为 `n + d/B`。
窗口 j 包含子步 `jM ... (j+1)M-1`，全局屏障位于每个 A 窗口末尾。
若 spike 在窗口 j 的第 r 个子步发放，延迟为 qA，则到期于窗口 j+q 的第 r 个子步。
spike 消息携带绝对发放步号 n，环形时间桶及事件记录保留到期步，IM 按到期步选择独立缓冲，不能将一个窗口内的输入压成单个值。

### 4.2 一次状态读取推进多个子步

因为最小突触延迟为 A，窗口内新产生的 spike 不会反过来影响同一窗口内的其他神经元更新。
在当前窗口所需输入准备完成后，NM 可以将神经元状态从 HBM 读入 NC，
使用各子步对应的输入连续推进 M 个最小步，期间状态保留在 NC，最后批量写回窗口末状态。
这样一次状态读取可以服务多个最小步，不需要每个 B 步都往返 HBM。
“一次读取”指覆盖完整状态的逻辑读取，实际仍按 HBM 事务粒度拆分。

例如 B=1、A=4，则 M=4：一次读入状态后依次使用四个子步的输入更新，产生各子步的 spike，
窗口完成后写回状态，再通过全局屏障进入下一窗口。A=B 时退化为原有的单步流程。

### 4.3 窗口内的模块重叠与同步

| 模块 | 当前窗口 j 内的工作                                                                         |
| ---- | ------------------------------------------------------------------------------------------- |
| NM   | 读取并保留状态，消费当前窗口 M 个子步的输入，逐子步更新并产生 spike。                       |
| EM   | 接收当前窗口的瞬时 spike 通知，创建带到期窗口和子步的事件；结合历史事件调度下一窗口的工作。 |
| PF   | 并发预取下一窗口各子步激活的突触，记录事件与子步上下文。                                    |
| IM   | 从当前窗口的 M 个步缓冲向 NM 提供输入，同时向下一窗口的 M 个步缓冲分别累加各步、各通道的权重和。 |

NM 在 CGRA 更新任务中保存绝对仿真步号，结果到达后将该步号写入 spike；调度器原样广播完整消息。
若 EM 推迟展开事件，其待查表记录仍保存完整 spike，不能用后续处理时刻代替消息中的发放步。

窗口结束时，调度器等待所有 PE 完成当前窗口的神经元更新，并处理完下一窗口输入所依赖的事件、尚未完成的 spike 索引和组描述查询、
预取返回及累加操作，再允许消费下一窗口输入。状态可通过 NC 继续提供或在写回后重新读取。
更远窗口的事件继续留在时间桶中，不要求屏障排空所有未来事件。
首版没有实际 NoC 在途消息；真实 NoC 的完成检测与屏障协议移至 [后续注意事项](notice_me.md)，
后续网络实现须完整保留 spike 中的发放者 ID 和发放步号。

## 6. 性能评估方法

1. **HBM 带宽利用率：** 实际 HBM 读写带宽与配置峰值带宽的比值。充分用满 HBM 带宽是此类工作的首要目标。
2. **实际吞吐 / 理想吞吐：** 在相同工作负载、硬件配置和吞吐统计口径下，比较实际吞吐与理想上限，衡量距离上限还有多远。

以上时间均采用被模拟硬件的执行时间，不使用 SoftSim 在宿主机上的运行时间。

## 7. 与现有内存模块衔接

目前 `RamulatorWrapper` 已提供独立通道实例，可以对应 PE 的私有 HBM 通道。
功能数据与 backing store 的分工见第 3.4 节。

- 上层使用“通道编号 + 通道内字节地址”，负责各数据区与溢出区的地址分配。
- 连续流需要通过 `splitChannelRequest()` 按后端事务边界拆分，并自行汇总完成状态。
- 每笔子请求按所属组件及读写方向检查和预扣 credit，完成时归还，遵循第 3.5 节；请求登记不等于已经发放，无 credit 时保留待发请求。
- `RamulatorWrapper::send()` 的通用接口仍可返回 false，表示请求未被接受；首版上层通过 credit 与队列容量约束保证合法发放成功，若仍返回 false 则报错终止，不能作为正常反压重试。
- 回调可能在 `send()` 返回前同步执行；先准备回调状态，回调内仅记录完成或更新状态，
  在外部调度阶段继续派发，不能重入后端。
- 内存完成回调不代替功能数据可见性、Isyn 累加完成或神经仿真步完成判断。
- 内存周期与 PE/CGRA 周期的换算由上层调度器定义。

后端接口的具体规则以 [RamulatorWrapper 文档](ramulator_wrapper.md) 为准；credit 容量约束与意外拒绝报错是首版上层的附加约定。
